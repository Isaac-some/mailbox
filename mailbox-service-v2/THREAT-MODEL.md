# 威胁模型

## 资产与信任区

- 资产：邮箱密码与 OAuth refresh token、邮件正文和附件、10 名成员身份、任务完整性、审计记录和备份密钥。
- 浏览器成员区：成员可共同查看全部邮箱；普通成员不能创建/删除成员或删除邮箱。
- Web 区：只处理 HTTPS 请求、会话和数据库读写，不拥有直接邮件网络调用权限。
- Worker 区：通过数据库租约读取已授权密文并访问外部 IMAP/SMTP；不能改变用户权限。
- 数据库区：保存密文、邮件、任务和审计；生产仅内网可达。
- 外部邮箱厂商区：通过 IMAP 993、SMTP 465/587 或 OAuth token endpoint 交互。

## 主要攻击故事与控制

| 优先级 | 场景 | 既有控制 | 剩余要求 |
|---|---|---|---|
| 高 | 数据库泄露后直接得到邮箱密码 | AES-256-GCM，主密钥不入库 | 备份同时保护数据库与 key；轮换 key 需迁移工具 |
| 高 | 普通成员删除共享邮箱或成员 | 角色检查、删除前输入完整地址、审计 | 生产试运行验证管理员账号隔离 |
| 高 | CSRF 借成员会话发起发件/删除 | SameSite=strict、Origin 校验、CSRF token | HTTPS 反代必须正确传递 Origin |
| 高 | 两个 Worker 同时连接同一厂商 | 数据库 provider gate 租约、3 秒连接间隔 | 监控 lease expiry 与连接数 |
| 中 | Worker 崩溃造成任务丢失或重复 | DB task lease、过期恢复、account active unique index | 7 天演练重启与断电恢复 |
| 中 | 邮件 HTML 注入运营后台 | 按需读取、`sanitize-html` 白名单、CSP、禁止 img | 继续用不执行脚本的正文展示策略 |
| 中 | 登录暴力尝试 | IP+用户名失败窗口，5 次后 15 分钟封禁 | 反代需保留真实客户端 IP 的可信配置 |
| 低 | 导出清单泄露邮箱地址 | 仅登录成员可导出，不导出凭证 | 生产审计导出行为并限制下载留存 |

## 明确不承诺

单一公网 IP 无法保证不被邮箱厂商封禁；系统只通过并发上限、厂商级间隔、指数退避、暂停窗口和观测降低概率。第三方 OAuth 服务或邮箱厂商本身遭入侵不在本系统控制范围。
