## 本次行为

- 账号来源为手动 CSV。所有生产平台拉取入口统一替换为无网络实现；旧配置即使 Enabled=true 也会强制关闭并清空 Endpoint/BearerToken。构建流程不再接受或编译平台 Token。

- 出现限流后同厂商后续后台任务冷却 60 秒，包含已经排队的任务；其他厂商和手动通道不受这个本地冷却影响。HTTP 429 和 IMAP 限流文字均按限流处理。

## 官方依据与边界

- [Microsoft Graph Outlook 限流](https://learn.microsoft.com/en-us/graph/throttling-limits#outlook-service-limits)：按 app ID + 单邮箱组合限额，4 个并发请求。这个数是 Graph API 限额，不能套用为 IMAP 登录或同 IP 跨账号的保证。
- [Gmail 客户端连接说明](https://support.google.com/mail/answer/7126229?hl=en)：同一账号最多同时添加 15 个客户端，连接过多可能报错。这不是同 IP 批量登录 15 个账号的保证。
- [GMX 官方 IMAP 连接资料](https://support.gmx.com/pop-imap/imap/server.html) 提供服务器、端口和 TLS 要求，但没有在该文档公布跨账号的安全并发额度。
- 未找到足以保证 Yahoo/GMX“每个出口固定可开 2–3 个”的官方依据，因此采用实际测试与限流反馈，而非把未知配额当作保证。
