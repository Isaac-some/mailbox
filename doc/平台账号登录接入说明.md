# 平台账号登录接入说明

邮箱助手发布版启动后强制显示登录页。BPO 使用平台账号登录：普通账号用于日常拉取，管理员账号仅在需要管理功能时使用。账号是否有效、账号角色和密码都由平台控制，邮箱助手不保存平台密码。

登录请求：

```http
POST https://openrouter.tuchong.com/api/auth/login
Content-Type: application/json

{"username":"平台账号","password":"平台密码"}
```

平台登录成功后应返回 HTTP 200，并通过 `Set-Cookie` 返回会话 Cookie；如果采用 Bearer Token，也可以在 JSON 的 `data.accessToken`、`data.token` 或 `accessToken` 字段返回。邮箱助手只在当前运行内存中保存会话，退出或重新打开应用后必须重新登录。

邮箱接口保持 `GET /api/external/account-credentials`。邮箱助手会转发登录得到的 Cookie 或 Bearer Token，并继续携带安装标识、设备名、系统和应用版本。平台必须在每次邮箱接口请求时检查会话对应账号仍然有效；账号停用后返回 `401` 或 `403`，客户端清除会话并要求重新登录。

成功响应继续使用接口指引中的 `data.total/items/serverTime` 结构。客户端第一次拉全量，之后使用 `updatedSince=<上次serverTime>` 增量拉取；任何一条记录校验失败时不推进增量游标。

研发需要确认：登录成功的会话返回方式、邮箱接口接受的鉴权方式、停用账号返回 `401/403`，以及角色字段 `role: "admin"` 或 `isAdmin: true`。客户端不会接受用户自行填写的角色。

平台或网关可以看到来源 IP；客户端同时发送安装标识、设备名、系统和版本。IP 能定位网络出口或大致区域，不能提供 GPS 位置。平台日志至少保留时间、账号、来源 IP、安装标识、设备信息和结果状态。
