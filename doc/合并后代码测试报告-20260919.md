**完整异常堆栈没有保留下来。** 失败处理会通过 `ILogger` 记录异常，但当前打包应用的标准输出与标准错误均指向 `/dev/null`；配置只有日志级别、没有文件日志接收端；macOS 统一日志中也没有上述 3 个任务的条目。同步任务数据库只保存失败状态，不保存原始异常文本。因此无法诚实地补出“当时捕获到的完整后台堆栈”。这是本次测试发现的可追溯性缺陷，不是“没有失败”。

### 根因判断

三个 Gmail 凭据清理空格及不可见字符后，长度分别为 **11、11、20**，而 Gmail 连接器要求 Google 应用专用密码必须**恰好 16 位**（4-4-4-4 的分组空格可以有，会被正确清理）。所以这 3 条凭据会在认证前被拒绝，不能进入真实收发测试。当前错误映射没有识别这种格式异常，最终回退为笼统的“邮箱同步失败”，不满足“准确说明一个错误原因”的要求。

要让下次能保留可审计的失败日志，应把同步任务的结构化错误码、脱敏异常类别和关联任务 ID 写入 SQLite 文件日志；界面根据错误码显示“Gmail 应用专用密码清理后不是 16 位”，而不是泛化为同步失败。该改动不属于本次“只测试”范围，未实施。
