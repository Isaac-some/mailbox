# 邮箱助手 v2.1.0 网络策略真实环境交接测试用例

## 给执行测试的 AI

你正在验证邮箱助手 `v2.1.0` 的 macOS 版本。目标是确认：应用不再引入统一公共代理出口，而是跟随每台设备自己的系统代理、PAC、VPN 路由或直连网络。

本次只做真实环境验收，不修改源码，不生成 Windows 版本，不上传 GitHub，不读取 GW、FlClash、IPRoyal 等私有配置，也不修改 macOS 系统代理设置。

## 测试用例

**编号**：NET-IP-001
**名称**：两台 Mac 使用不同 VPN 节点完成安全收件，并验证 VPN 关闭后的自动直连
**版本**：`v2.1.0`，macOS Apple Silicon，build `210`

## 前置条件

1. 准备两台 Mac，均安装同一个 `v2.1.0` 版本。
2. 两台 Mac 使用不同的 VPN 节点。记录节点名称即可，不要记录账号或密钥。
3. 准备一个允许低频读取的测试邮箱。两台设备可以使用同一个测试邮箱，但每台只做一次连接检测和一次少量收件同步。
4. 准备组织控制的 HTTPS 出口检测地址，例如：`https://<组织提供的出口检测地址>`。该地址只用于本次验收，不要把第三方公网 IP 查询服务加入应用配置。
5. 如果测试包尚未提供，向交接人索取 macOS DMG；不要自行改用旧版本。

## 操作步骤

### A. 确认应用网络策略

在两台 Mac 上：

1. 打开邮箱助手，进入“本机数据 → 网络策略”。
2. 选择“自动跟随本机网络”。
3. 保存设置。
4. 确认没有填写固定代理主机、端口或凭据。

预期：界面说明自动模式会跟随本机系统代理、PAC、环境代理和 VPN 路由。

### B. 验证两台设备使用各自出口

1. Mac A 连接 VPN 节点 A，Mac B 连接 VPN 节点 B。
2. 在两台 Mac 的浏览器中分别访问组织 HTTPS 出口检测地址。
3. 记录两台设备观察到的公网 IP，或记录组织服务返回的脱敏编号。
4. 在两台 Mac 上各打开“网络诊断”，目标填写组织 HTTPS 地址，点击“开始检测”。

预期：

- 两台设备的观察到的出口 IP 不同；如果相同，记录为失败，不要自行推断原因。
- 网络诊断显示目标主机、目标端口、路由类型、检测阶段、成功状态和诊断编号。
- 诊断结果不显示完整邮箱地址、Token、代理密码或完整代理 URL。

### C. 验证邮箱请求经过统一网络策略

在两台 Mac 上分别执行：

1. 添加同一个测试邮箱。
2. 执行一次“连接检测”。
3. 执行一次安全收件同步，只读取少量邮件。
4. 记录连接检测和收件同步是否成功，以及错误阶段（若失败）。

预期：

- 两台设备都使用各自当前 VPN 节点的网络路径。
- IMAP、SMTP、OAuth、Graph 和 Token 刷新不能绕过网络策略层。
- 连接失败时应区分代理连接、目标连接、TLS、协议欢迎、邮箱认证和限流阶段。
- 不应出现固定公共代理地址或固定统一出口。

### D. 验证 VPN 关闭后的自动直连

1. 只在 Mac A 上关闭 VPN，保持 Mac A 的网络策略为“自动跟随本机网络”。
2. 等待网络状态稳定后，再执行一次安全收件同步。
3. 再次访问组织 HTTPS 出口检测地址，记录 Mac A 当前出口。

预期：

- 应用使用 Mac A 当前设备的直连网络完成收件，或明确报告当前网络不可用。
- 如果原系统代理入口失效后触发回退，界面或日志应提示：`代理不可用，已临时使用本机直连`。
- 不允许回退到应用内置代理或其他固定出口。
- 不强行迁移已经建立的 IMAP/SMTP 长连接；下一次操作使用新路由即可。

### E. 验证应用不修改系统代理

在安装前和测试完成后分别打开 macOS“系统设置 → 网络 → 代理”，比较以下内容：

- HTTP/HTTPS/SOCKS 代理开关；
- 代理服务器地址和端口；
- PAC 自动代理配置。

预期：安装和运行邮箱助手前后系统代理设置完全一致。

## 可选的指定代理拒绝测试

如果现场有一台可控的本机 HTTP 或 SOCKS5 代理：

1. 在“网络策略”中改为“指定本机代理”，填写该代理的主机、端口和必要凭据。
2. 停止代理，或让代理拒绝目标邮箱的 `993` 端口。
3. 执行连接检测。

预期：

- 直接报告代理不可用或代理拒绝目标。
- 不自动改走直连。
- `CONNECT 403` 应归类为代理拒绝，不得误报成邮箱密码错误。
- 不进行无限重试。

## 通过标准

本用例只有在以下条件全部满足时才算通过：

1. 两台不同 VPN 节点设备的出口 IP 或组织脱敏编号不同。
2. 两台设备各完成一次连接检测和一次安全收件，或得到准确的分阶段错误。
3. VPN 关闭后，自动模式只使用本机直连作为回退。
4. 指定代理失败时不发生直连（若执行可选测试）。
5. 应用没有修改 macOS 系统代理设置。
6. 应用日志和诊断结果没有完整公网 IP、邮箱账号、Token 或代理凭据。

“出口 IP 不同”只证明应用没有人为引入统一出口；如果两台设备使用同一 VPN 节点、同一局域网或同一上游 NAT，公网 IP 相同不能单独归咎于应用。

## 失败时必须保留的证据

- 测试设备和 VPN 节点名称；
- 两台出口检测结果（公网 IP 可只保留前两段和后两段）；
- 连接检测和收件同步的成功/失败状态；
- 网络诊断页面截图；
- 错误原文和发生阶段；
- 系统代理设置前后对比截图。

不要提交邮箱密码、OAuth Token、代理密码、完整邮箱地址或邮件正文。
